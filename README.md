- Python 3.8+，仅标准库（不允许第三方运行时依赖）；

## 3. AI 会话归档（pre-commit）

本课程允许使用 AI，提交的 commit 需要携带 AI 会话归档作为透明化记录：每次 `git commit` 后，钩子会把新增会话自动 amend 进同一个提交（`.agent-sessions/bundles/`），不产生额外的归档提交。支持 Claude Code、OpenAI Codex CLI、GitHub Copilot CLI、Qoder、ZCode、Trae、Tencent CodeBuddy 等（完整名单见 [AgentLedger](https://github.com/Gentle-Lijie/AgentLedger)）。

- 配置是仓库本地的：每个 clone 运行一次 `agent-session-commit install --pre-commit`，方向键选择 agent、确认其会话目录即可；
- 不想用 TUI 可手动配置：`git config --local agent-session.agent claude`、`git config --local agent-session.source "<会话目录>"`，然后 `python -m pip install 'pre-commit>=3.2.0' && pre-commit install`；
- 归档是普通 Git 内容且会推送到公开仓库——不要在 AI 会话里粘贴令牌等敏感信息；
- 换了 agent 或目录就重跑一次安装命令；卸载：从 `.pre-commit-config.yaml` 移除该条目后重跑 `pre-commit install`。

## 6. 实现思路与边界假设（你来写）

以下说明对应当前代码。Q1–Q5、Q7 已实现；题面没有明确展开的边界采用了下述选择，这些选择不代表已经获得课程方确认或通过隐藏测试。

### Q1：机器人自检

- 将血量和满血量先转为整数，计算百分比时使用 Python 的 `round`，再将结果限制在 0–100。`round` 在恰好位于中点时采用取偶规则，并非所有情况都按通常的“四舍五入”理解。
- 血量转换出现 `ValueError`、`TypeError`，或满血量不大于零时返回 0。当前实现并不保证覆盖所有极端数值输入。
- 报告复用血量计算函数，用格式化字符串实现名称左对齐、机型居中和百分比右对齐。
- 电量先转整数，转换出现上述两类异常时使用 0；电量本身未限制在 0–100。分档暂定为：`>= 50` 是 `OK`，`<= 20` 是 `LOW`，中间是 `WARNING`。取整及分档边界仍待确认。

### Q2：战斗日志分析

- 将传感器行与 JSON 行统一解析为“部位、伤害”事件，再累计总伤害及三个部位的伤害。每行先暂存事件，全部校验通过后才更新统计，避免部分损坏的行被计入一部分。
- 跳过非字符串元素、空行、注释及无法解析的行。JSON 伤害只接受严格正整数，排除布尔值、浮点数和数字字符串；传感器数值接受 ASCII 数字组成的正整数文本，并允许字段两端有空白。
- 带 ID 的有效 JSON 行通过集合去重；无 ID 的行独立计数。只有有效行才登记 ID，不可哈希的 ID 按脏行处理；可哈希 ID 按 Python 集合的相等性规则比较，没有额外按类型区分。
- 平均伤害按有效事件数计算，一条传感器行可贡献多个事件，使用 `round(total / count, 2)`。最大伤害部位并列时按 `front → left → right` 优先；没有有效事件时返回 `most_hit=None`、`avg=0.0`。事件平均口径、并列顺序及 ID 边界属于当前实现选择。

### Q3：载体移动与转向

- 位置赋值只接受长度为 2 的列表或元组，复用 `_clamp_cell` 转整数并夹回地图范围，拒绝落在障碍上的位置；全部检查成功后才更新坐标，异常时保留旧位置。构造函数仍保留原始实现。
- 有电时，每次前进尝试消耗 1 单位电量。障碍和越界均视为碰撞，位置、朝向不变，碰撞次数加 1；没有阻挡才移动。
- 电量不大于零时，前进直接返回原位置，不再扣电或增加碰撞次数。左右转通过方向映射实现，只改变朝向，不耗电，断电时也允许转向。
- setter 的夹回边界策略、碰撞耗电及断电计数口径是当前采用的一致性选择，不能由可见测试推断为全部隐藏边界要求。

### Q4：贪心导航

- 用曼哈顿距离衡量与目标的差距，按横纵坐标差安排方向检查顺序，返回第一个无障碍且严格减距的方向。
- 横向差更大时优先横轴，否则优先纵轴，因此相等时采用纵轴优先。首选方向被挡住时继续检查其余方向；全部不符合或已经到达目标时返回原朝向。
- 本函数只选择方向，不执行移动，也不检查地图边界。原朝向是回退结果，不保证沿该方向移动安全；贪心无法绕出死角是策略局限。平局时优先哪个轴仍待确认。

### Q5：哨兵决策

- 先检查必要字段、状态类型和帧历史形状，再计算当前可见性、末两帧确认情况及末尾连续丢失次数。按 R1–R7 顺序执行，首条命中立即返回，不修改输入字典。
- 血量百分比复用 Q1，低于等于 30% 时优先撤退。恢复阈值暂定为 80%，持续丢失阈值暂定为 3 帧；这两个数值尚未获得课程方确认。
- 敌距的非负数值转为整数，无法转换、负数或未知值按正无穷处理；例如 `3.8` 会被转为 `3`，这一归一选择可能影响临界决策。非法机型默认按步兵处理。
- 满血量转为至少 1 的整数，非法值使用 1；当前血量转整数并限制在 0–满血量，非法值使用 0。帧元素按真值解释，非法帧容器或长度直接抛出 `ValueError`。这些防御式规则仍需与课程的具体归一要求核对。
- 当前公开规则没有规定热量分支，因此保留 `heat` 参数，但不自行增加过热停火规则。`RETURN` 只作为一次决策的过渡状态。

### Q7：旧版巡逻模块调试

以函数 docstring 为验收依据，先运行完整测试定位首个失败，再逐项检查单位、边界和循环状态；没有修改测试或 CI 配置。六处主要缺陷与定位过程如下：

1. 路线单位错误：测试期望 7 米，实际得到 700；沿调用链发现 `segment_length_cm` 返回厘米，因此在累计米数时除以 100，保留底层函数的厘米契约。
2. 无正样本时未处理空基线：`first_positive` 返回 `None`，继续做减法会抛异常；按契约直接返回漂移 0。
3. 事件上限漏算：契约是 ID“不超过”上限，原条件 `< max_id` 排除了边界事件，改为 `<= max_id`。纳入边界事件后，无正样本问题也会暴露。
4. 默认日志串联：连续调用发现上次记录残留；默认列表只在函数定义时创建一次，改用 `None`，在每次未提供历史时新建列表；显式传入的列表仍原地追加。
5. 模拟退出条件反向：原代码在体力大于 20 时退出，与“每轮结束后体力不大于 20 时停止”相反，改为 `<= 20`。
6. 模拟轮号不递增：退出条件修正后暴露死循环风险；每轮记录完成后递增轮号，确保按轮数上限结束，并使第 4 轮起的额外消耗生效。

另按脏行不得抛异常的契约补强 `parse_event`：非字符串返回 `None`，捕获数字转换失败；例如某些 Unicode 数字虽然通过 `isdigit()`，却不能转换为整数。没有扩大事件类型或改变原有非负计数格式。
